### 6. Imagen de perfil (Avatar upload)

**Supabase Storage:**
- Bucket `avatars` creado como público
- Políticas RLS en `storage.objects`:
```sql
CREATE POLICY "avatars_insert" ON storage.objects FOR INSERT TO authenticated
  WITH CHECK (bucket_id = 'avatars');
CREATE POLICY "avatars_update" ON storage.objects FOR UPDATE TO authenticated
  USING (bucket_id = 'avatars');
CREATE POLICY "avatars_select" ON storage.objects FOR SELECT TO public
  USING (bucket_id = 'avatars');
```

**Archivos nuevos:**
- `src/components/AvatarUpload.tsx` — componente reutilizable: muestra foto actual (o iniciales), permite cambiarla con click. Valida tipo imagen y máx 2MB. Sube directamente al Storage desde el browser, luego actualiza `foto_url` vía API.
- `src/pages/api/actualizar-avatar.ts` — endpoint que actualiza `usuarios.foto_url` para el usuario autenticado.

**Archivos modificados:**
- `src/lib/types.ts` — `TecnicoDisplay` incluye `foto_url`; `tecnicoToDisplay` mapea el campo
- `src/components/Navbar.tsx` — query incluye `foto_url`; muestra foto en avatar (desktop y mobile) con fallback a iniciales
- `src/components/FiltroTecnicos.tsx` — cards de técnicos muestran foto con fallback a iniciales; tipo actualizado de `mockTecnicos.Tecnico` a `TecnicoDisplay`
- `src/pages/tecnicos/[id].astro` — perfil del técnico muestra foto
- `src/pages/dashboard/cliente.astro` — query incluye `foto_url`; sección "Mi perfil" incluye `AvatarUpload`
- `src/pages/dashboard/tecnico.astro` — sección "Mi perfil público" incluye `AvatarUpload`

**Comportamiento:** el campo `foto_url` ya existía en `usuarios`. La foto se almacena en `avatars/{userId}.{ext}` con upsert (reemplaza al cambiar).

### 7. Múltiples categorías por técnico

**Formulario de registro (`RegistroForm.tsx`):**
- Reemplazado el select de una sola especialidad por un grid de checkboxes
- Schema actualizado: `especialidades: z.array(z.string()).min(1, ...)`
- Se envían todas las especialidades seleccionadas al endpoint

**API registro (`pages/api/registro-tecnico.ts`):**
- Recibe `especialidades: string[]` en lugar de `especialidad: string`
- Busca los IDs de todas las categorías por nombre y crea múltiples filas en `especialidades_tecnico`

**Archivos nuevos:**
- `src/components/GestionEspecialidades.tsx` — componente React para el dashboard. Muestra las especialidades actuales como pills con × para quitar; muestra las disponibles como botones + para agregar. Llamadas instantáneas sin recargar la página.
- `src/pages/api/gestionar-especialidades.ts` — endpoint que recibe `{ accion: 'agregar'|'quitar', tecnicoId, categoriaId }`. Verifica que el técnico pertenezca al usuario autenticado antes de operar.

**Dashboard técnico (`dashboard/tecnico.astro`):**
- Query de `especialidades_tecnico` incluye ahora el campo `id` de categorías
- Se agrega query de todas las categorías activas (`todasCategorias`)
- El campo estático "Especialidad" fue reemplazado por `<GestionEspecialidades />`
