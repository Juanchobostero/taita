### Item 8 — Verificación de email (completado)

`verificar-email.astro` y `ResendVerification.tsx` ya existían de la sesión anterior. Se completó el flujo corrigiendo:

- **URL dinámica**: `emailRedirectTo: window.location.origin + '/'` en ambos formularios. Funciona en local (`localhost:4321`) y en Vercel sin hardcodear nada.
- **Bug de teléfono con email confirmation ON**: con la sesión null tras el signUp, el browser client no puede hacer updates autenticados. Fix:
  - **Cliente**: teléfono pasa en `options.data.telefono` del signUp → el trigger de Supabase lo persiste. SQL ejecutado:
    ```sql
    CREATE OR REPLACE FUNCTION public.handle_new_user()
    RETURNS trigger AS $$
    BEGIN
      INSERT INTO public.usuarios (id, nombre_completo, email, tipo, telefono)
      VALUES (
        NEW.id,
        NEW.raw_user_meta_data->>'nombre_completo',
        NEW.email,
        NEW.raw_user_meta_data->>'tipo',
        NULLIF(NEW.raw_user_meta_data->>'telefono', '')
      )
      ON CONFLICT (id) DO NOTHING;
      RETURN NEW;
    END;
    $$ LANGUAGE plpgsql SECURITY DEFINER;
    ```
  - **Técnico**: teléfono pasa al endpoint `/api/registro-tecnico` (admin client, sin RLS).
- **Supabase configurado**: Enable email confirmations activado. Redirect URLs:
  - `http://localhost:4321/**`
  - `https://tu-app.vercel.app/**` (pendiente completar con URL real)

**Dead code limpiado en `RegistroForm.tsx`:**
- Eliminado `SuccessMessage` component (ya no se usa)
- Eliminado estado `success` de ambos forms
- Eliminado import `Select` sin usar
- Fix Zod v4: `invalid_type_error` → `.min(0, 'mensaje')`
- Fix Zod v4: `.or(z.literal(''))` → `.optional()` (causaba crash del resolver)
- Fix Zod v4: `.default(true)` → `.optional()` con `?? true` en submit
- Fix react-hook-form: `watch('especialidades') ?? []` → `Array.isArray(raw) ? raw : []` (devolvía `false` en estado inicial)
